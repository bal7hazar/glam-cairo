## Why

nalgebra-cairo (escalation of 2026-09-24, relayed by the programme session) composes `sinh`,
`cosh`, `tanh` from two `exp` today; its `Real` trait mirrors simba's `ComplexField`, which has
them (and `sinhc`). They belong to the scalar, like `f64::sinh` in Rust.

## API (new methods of `ExpTrait`, full doc template)

`sinh(self) -> Fixed`, `cosh(self) -> Fixed`, `tanh(self) -> Fixed`, and `sinhc(self) -> Fixed`
(`sinh(x) / x`, `sinhc(0) = 1`). Check simba 0.10's `ComplexField` for the exact name and meaning
of `sinhc` (and whether `coshc` exists there) and mirror them; do not add anything else (no
`asinh` / `acosh` / `atanh`: not requested; say in the report if nalgebra would need them).

## Numerics (measure; winner in the library, losers in `benches::alt::exp`)

- Accuracy against a high-precision oracle (mpmath in the Python mirror, and/or the Rust `f64`
  functions through `tools/refgen`, which is more than precise enough for a Q32.32 result):
  report the max error in ULP per function and per range; target the same order as `exp` (<= ~2
  ULP) and state the bound on each item.
- Required properties, tested: `sinh`, `tanh`, `sinhc` exact symmetry (`sinh(-x) == -sinh(x)`,
  `tanh` odd, `cosh` / `sinhc` even, bit for bit); monotonicity (`sinh`, `tanh` increasing,
  `cosh` increasing on `x >= 0`), checked on a dense grid and at segment junctions like `exp`;
  `tanh` saturates to exactly `+-ONE` beyond the point where `1 - tanh` is below half an ULP,
  never panics; `sinh` / `cosh` panic `'Fixed: overflow'` beyond `asinh(2^31)` / `acosh(2^31)`
  (about 22.18): derive and test the exact raw boundary; small `|x|`: no cancellation (`sinh`
  from `exp_m1` or a dedicated polynomial, not `(e^x - e^-x) / 2`).
- Candidates: compositions of `exp` / `exp_m1` (one shared `exp` for `sinh` + `cosh`: a
  `sinh_cosh` helper if it pays, as `sin_cos` does), `tanh = em1(2x) / (em1(2x) + 2)`, versus a
  dedicated minimax segment near 0 generated by `gen_exp.py`. Bench each (`X__base` / `X__op`,
  `bb` inputs, several inputs for branching code).
- Rounding of the final rescale: floor like `exp` unless round-to-nearest keeps monotonicity
  (DESIGN 2); decide by the generator's check and document it.
- If new coefficients are generated: pin the Python environment first (debt D1: `gen_trig.py` /
  `gen_exp.py` need numpy / mpmath and their fits change with the numpy version). Add a
  `scripts/requirements.txt` with exact versions and the venv command in the script docstring,
  so that `gen_exp.py check` is reproducible; say whether the committed `exp` coefficients are
  reproduced under the pinned versions.
